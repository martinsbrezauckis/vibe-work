# protocol

Generated TypeScript types for the Vibe app-server protocol (`generated/`) and the typed
command client (`client/`). The UI never speaks JSON-RPC: it only calls the typed commands exposed here.

`generated/` is written by `tools/public/codegen/generate.py` from Vibe's own Pydantic models and is
never edited by hand; every file carries a header naming the generator and the Vibe version, and
`scripts/public/check.sh` fails if regenerating produces a difference. Import from
`generated/index.ts` (types) and `generated/methods.ts` (method name to params/result maps).
Optional versus null follows Pydantic exactly: `x?: T` may be absent, `x: T | null` must be present
and may be null, `x?: T | null` may be either. Discriminated unions include `Unrecognized<tag>` for
payloads from a newer Vibe; handle it in the `default` branch.

`core/` holds the TypeScript form of the core command API (`Command`, `CommandResult`, `CoreEvent`,
`CoreError`), generated by `crates/vw-core-api` (binary `gen-core-ts`, ts-rs) from the Rust types the
Debug API and the Tauri bridge share. Never edited by hand; `scripts/public/check.sh` fails on drift.

`client/` is the typed client over the core API: `types.ts` (the `CoreClient` interface),
`tauriClient.ts` (invoke + Channel, the five granted commands), `debugApiClient.ts` (browser dev mode through
the Vite dev proxy, `vite.dev-bridge.ts`), `select.ts`. Components never import a client; the shell gets one
through `state/coreStore.ts`.
