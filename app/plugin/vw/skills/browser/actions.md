# Browser action arguments

`browser_act`: `navigate {url}`, `list_tabs`, `close_tab {tab: id}`, `back`, `forward`, `reload`, `click {ref}` or `{x, y, ref?}` (viewport CSS pixels), `drag {ref, to}`, `type {ref, text, submit?}` (replaces text; submit presses Enter), `select {ref, value}` or `select {ref, values}` (multiple native options; `values: []` clears them), `check {ref, checked}`, `press {key, ref?}`, `scroll {ref | direction}`, `hover {ref}`, `wait {text | ref | load, timeoutMs}`, `upload {ref, paths}` (files from this chat's folders; `paths: []` clears selected files; file pickers never open for you). Refs come from the latest `browser_read`; stale refs are refused. `list_tabs` gives `tabs` (id/site/owner/active/suspended; title/URL under `untrustedPageContent.tabs`). If shortened, continue with `browser_act({action: "list_tabs", tab: result.nextTab})`.
Rich-text reads include rendered editor text. Native form controls include current validity and an invalid field's validation message; reading does not open validation UI. Input receipts verify the current state after page handlers settle.
Native date fields take `YYYY-MM-DD`; text datepickers use the page's displayed format.

`browser_read {selector: {kind: "css" | "xpath" | "alt" | "title" | "testId", value, index?}}` returns matching element refs and `matches.count/complete`. Attribute matches are exact; CSS enters open shadow roots, XPath follows document semantics. `index` selects one of the first 200 matches, zero-based in document order, main document then frames. The count covers the scanned DOM before output limits; unreadable frames or a capped scan make it incomplete. Selector reads omit `find` and continuation cursors.

Everyday actions use the same names as Your Chrome, with arguments directly in `browser_act`:

- `page.dialogs` reads the held native alert, confirm, prompt, leave-page or HTTP sign-in dialog, even while page JavaScript is blocked. Answer its exact `dialogId` with `page.dialog.accept`, `page.dialog.dismiss`, or `page.dialog.prompt {text}`. A click or navigation that opens a dialog returns that dialog; answer it and read the result before repeating the input. Stop dismisses held dialogs. Reading and dismissing run in Ask; accepting a dialog and entering prompt text ask.
- `auth.basic {url, login, dialogId?}` answers HTTP Basic sign-in using a saved vault login name or id, with a browser approval card below Full access and the existing separate vault approval. It checks the native challenge's origin and reports whether the checked site loaded; credentials never appear in the tool. Read `page.dialogs` after a refusal. If the login is missing, ask the user to save or choose it in the vault. Never supply credentials as text or URL arguments.
- `page.double_click`, `page.right_click`, `page.middle_click`, and `page.triple_click` take `ref` or viewport `x, y` like `click`. `click` and all variants accept `modifiers: ["Alt", "Control", "Meta", "Shift"]` (choose the keys needed). These use checked native input; a failure after input says it may have acted and must not be repeated blindly.
- `files.download {url}` starts an HTTP(S) transfer using this page's profile cookies and returns `downloadId`. `files.wait_download {downloadId?, timeoutMs?}` waits at most 20 seconds; `timedOut` means unfinished. Omit the id only when this chat has exactly one download. Click receipts include newly observed `untrustedPageContent.downloads` with IDs. `files.list_downloads` lists this chat's recent downloads. Completed files are saved automatically to the chat's `downloads/` folder; `files.save_download {downloadId}` returns that artifact's path. A failed/interrupted download has no complete artifact. Wait before using a file. Ask: ordinary GET downloads need no approval; saving with `files.save_download` asks. Listing and waiting run.
- `window.open {url?}` creates an independent window with one new web page for this chat; an omitted URL opens a blank page. The receipt has `windowId` and `tab`. `list_tabs` includes window IDs. `window.focus {windowId}` brings that window forward and selects its page for the agent; `window.close {windowId}` closes it and its page. Window actions run in Ask, retain Stop and ownership checks, and never target another chat. Pass `tab` to ordinary page actions. Windows remain live under the browser engine limit; close one to free a slot.
- `capture.screenshot {ref? | clip?: {x, y, width, height}}` returns a PNG of one visible element or a viewport rectangle in CSS pixels. Omit both for the viewport. Scroll an offscreen element into view first. The usual vault screenshot restrictions apply.
- `cookies.metadata {names?}` lists current-site cookie attributes; `cookies.read {names?}` includes values and HttpOnly cookies. `cookies.change {operation: "set" | "remove" | "clear", name?, value?, path?, secure?, httpOnly?, sameSite?}` changes this site only. `set` needs name/value; `remove` needs name; path defaults to `/`.
- `storage.metadata {area: "local" | "session"}` lists keys. `storage.read {area, keys}` returns values or null. `storage.change {area, operation: "set" | "remove" | "clear", key?, value?}` changes the selected area; set needs key/value, remove needs key.
- `clipboard.read` and `clipboard.write {text}` transfer plain text for page work, at most 65536 UTF-8 bytes. Empty text clears it. Read reports `truncated` if capped. A live vault copy cannot be read.

`media.read` lists up to 32 main-document video/audio elements with `mediaId`, paused/muted state, position, duration and playback errors. `media.play`, `media.pause`, `media.seek {mediaId,timeMs}` and `media.mute {mediaId,muted}` return live state. `media.transcript {mediaId}` returns loaded caption cues (up to 12,000 characters); absent captions are explicit. Playback can fail because of the site's autoplay policy or source. Handles expire with the document or element. These actions run in Ask, Accept edits and Full access.

`tabs.audio` reads native muted/audible state; `tabs.mute {muted}` changes mute and reads it back (Chrome/Edge also require `tabId`). Built-in Linux and Windows use native tab audio. Built-in macOS reports unavailable and offers individual `media.mute` controls.

Local `file:` navigation opens a PDF, HTML or image from the chat's first folder, up to 32 MiB. The built-in browser grants the selected document only; other local paths and linked local resources remain unavailable. PDF rendering depends on the engine; `document_read` reads the saved PDF when the viewer exposes no page text.

`recording.start` begins a GIF of screenshots after browser actions; `recording.stop` saves it in the chat folder. It is bounded to 30 frames, two minutes and 8 MiB of source screenshots, with omitted frames reported. The GIF fits within 800×600; frame intervals are clipped to 0.1–5 seconds. It contains no audio. The user's Stop discards the recording. `recording.video.start/stop` report that this engine has no page-video encoder and name the GIF alternative.

`reload` accepts `bypassCache: true` to reload from the origin. The receipt contains the resulting page and whether navigation is still loading.

`page.inspect` takes `selector` for exactly one main-document element, optional `attribute`, and optional `properties` (up to 32 CSS names). It returns computed styles, bounds, a literal attribute and sanitized HTML (200 nodes / 1200 characters). Scripts, event handlers, hidden inputs and form values are omitted; `htmlTruncated` reports limits. Markup inspection is unavailable after a vault fill. This read runs in Ask.

`console.read` returns log/info/debug/warn/error entries; `page.errors` returns uncaught exceptions, unhandled promise rejections and failed resources from the current main document. Both accept `level`, `text`, `offset`, `limit` (1–100, default 25), or `last` instead of `offset`. `nextOffset` continues matching records; `dropped` counts entries lost from the bounded buffer. `console.clear` and `page.errors.clear` clear their respective buffers without reloading. The page can affect its own diagnostic capture. Reads and clears run in Ask.

`tabs.emulate` in the built-in Browser panel accepts `width` and `height` (240–4096 CSS pixels), or `preset: "phone" | "tablet" | "desktop"` (390×844, 768×1024, 1280×800). `reset:true` restores the panel's selected device width. The receipt measures the native viewport. User agent, touch and pixel density are unchanged. Sizes that cannot fit the panel refuse.

`window.resize {windowId,width,height}` measures the independent browser window's logical content area. Width is 400–4096 and height 300–4096; main app window ids refuse.

`raw.execute {expression,timeoutMs?}` runs one main-document JavaScript expression in the page world, including a Promise, and returns its bounded JSON result. The completion deadline is 100–5000 ms (default 5000). Exceptions, changed documents and timeouts report failures with potentially completed side effects. `page.add_style {css}` adds a current-document stylesheet and reports whether the page accepted it and its rule count. Both require Full access and exclude vault-filled documents. A document that received page code cannot receive a later vault password fill; navigation to a new document resets that exclusion.

`network.list` reads a bounded native request log with method, status, completion and transport errors. Filters: `url`, `method`, `status`, `failedOnly`; paging: `offset`, `limit` or `last`. `network.headers {requestId}` returns request/response headers with sensitive and unknown values redacted. `unredacted:true` requires Full access and refuses after a vault login. Query values are removed from listed URLs. The log is limited to 256 records and 2 MiB, resets on document navigation and reports dropped records and coverage limits. Windows and Linux have native request feeds; the current macOS engine reports unsupported rather than an empty log. Request/response bodies are not captured.

Built-in `tabs.emulate` accepts `colorScheme: "light" | "dark" | "system"` separately from size on Windows/macOS. The result contains the native media-query readback. WebKitGTK cannot override one view's color preference. `reset:true` restores size and color.

`page.add_style` also accepts `{css, tabId?}` through `chrome_execute` in Chrome, Edge, Firefox and Safari. It uses Full access and the same document/vault exclusion as `raw.execute`; its result includes the accepted rule count.

`chrome_execute` `console.clear {tabId?}` clears the retained-console view for this session tab. Later messages remain readable and `page.errors` stays independent. Cleared reads retain existing filters and paging.

Chrome/Edge `capture.screenshot {labels:true}` labels up to 12 visible controls on a PNG viewport copy. Returned numbers map to executable refs. It verifies locations before and after capture and leaves the page unchanged; inline output only.

In the user's browser, `capture.screenshot {compare:"before"}` stores a session/tab baseline where PNG viewport capture is supported; `compare:"after"` returns the current image, changed-pixel percentage and image-pixel bounds. The viewport, scale and origin must match. Comparisons count exact RGBA changes, including animations; at most eight baselines are retained.

`browser_read` with `extract:{kind:"table"|"list"|"links"}` and `saveTo:"csv"|"xlsx"` saves rendered rows in the chat folder. Optional `extract.selector` picks table roots or repeated items; list columns can use `{name,selector,attribute:"text"|"href"}`. Tables use named positional columns. `extract.index` selects a table across readable frames. The receipt contains file and collection names, row counts, sources and incomplete coverage. `appendFrom` adds captured pages to a previous collection; `deduplicate:true` removes identical rows. Each export creates new files. Page advance and scroll remain ordinary browser actions. CSV formula-like cells are text; spreadsheet cells contain no formulas.

Connected `chrome_execute` supports the same export options on one `page.read`. Table exports require `args.ref` for one table subtree; `args.interactiveOnly:false` exposes table/list structure. The returned cursor continues captured rows. `extract.header:false` keeps a continuation's first data row. Connected extraction supports table/list/link records and positional column names; CSS and relative-column queries are built-in-only. Saved rows cover the returned read, including its coverage limits.

Selector queries match a redacted DOM snapshot. Protected fields expose identity, label and state attributes; their other attributes and editor text are unavailable to predicates. Secret values and hidden text are absent; interaction-state CSS pseudo-classes are unavailable. Extraction excludes secret editor text, including when a selected parent contains it.

`browser_read {ref}` reads that retained DOM subtree, including open shadow roots, within its owning document. Nested frames have their own refs. `textPage` pages its text. A replaced or unreadable root refuses with a fresh-read instruction.

`browser_act {action:"form", fields:[{action:"type",ref,text},{action:"select",ref,value},{action:"check",ref,checked}]}` fills 1–16 fields through their ordinary checked actions. All arguments and initial refs are checked first. Each result is read back; a failure stops later fields and preserves earlier results. Submission is separate. The call uses the highest shared access requirement of its fields.

`clipboard.read_rich {mime}` and `clipboard.write_rich {mime, text? | base64?}` use the native clipboard in Full access. MIME is text/html or image/png; HTML input uses text (up to 60000 bytes), PNG uses base64 (up to 256 KiB decoded). Writes read back actual content, PNG reads return an image, and active vault copies are withheld. HTML is supported on Windows, macOS and Linux X11; the current Wayland backend refuses HTML with a reason and supports PNG/plain text. The chat mode itself must be Full access because writes also read clipboard content back; a write approval in a lower mode cannot authorize that readback.

- `window.list` reads native focus, visibility and size for this chat’s independent built-in windows without selecting a tab. Chrome/Edge/Firefox/Safari `windows.list` reads the current chat window’s native focus and geometry. Panel tab focus handles remain in `list_tabs`.

- Built-in `wheel {ref?,x?,y?,deltaX?,deltaY?}` sends bounded native wheel input on Windows/macOS/Linux, with the observed node/frame and event-time guard, then reports actual pane and document offsets. Deltas are integers from -20000 to 20000, at least one nonzero. Native scroll chaining/axis locking follows the engine. macOS delivers a public Quartz wheel event directly to the checked web view; if native geometry cannot be verified, use `scroll` with the intended pane ref.

- `highlight {ref,clear?}` outlines an observed visible target for 1500 ms without focusing it or sending input. Only one outline appears per document; clear:true removes it immediately.

- `browser_act {steps: [...]}` runs 1–16 ordinary action objects in order. Each step uses the same access tier, consent, target binding and Stop checks as a single action. It returns ordered actual receipts and stops on a refusal, unmet condition, unknown outcome, or execution/output budget. Site-secret reads are checked against Full access before the first step. Batches cannot nest; remaining steps are not automatically retried.

Transport retries with the same authenticated browser call identity reuse its one-use decision or return the original result marked `requestReplay`. A changed input under that identity is refused. Interrupted requests and evicted results never dispatch again; a deliberate new action has a new call identity. Cached site-secret results still require the current Full access mode.


An open user question hands this chat's browser back: capture and agent actions wait, the page stays open, and a confirmed answer permits the next browser action. Skip keeps browser work held until a new user message. Stop cancels browser work; a late answer cannot resume it.

Clearing all cookies or a complete storage area requires the chat itself to have Full access; a saved tool grant or browser approval card cannot substitute.

Ordinary text entry, `insert_text` and supported page keys use the native view's keyboard path. Results require trusted events at the exact retained field and a settled value read-back. A changed document or focus refuses input; an interrupted dispatched operation is never retried. Read the page after a failed or unknown result before another action. Native select popups and date/colour picker keys cannot provide that receipt: use `select` or the field's supported value action. Date/time, range/colour and calendar-widget value setters remain scripted. Clipboard shortcuts refuse because they bypass the protected clipboard; use `clipboard.read`/`clipboard.write` and `insert_text` instead. Copy/cut/paste authority remains Full only.
