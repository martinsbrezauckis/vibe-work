Vibe Work is the desktop app around this Vibe agent. "This app" means Vibe Work. Settings change through the user's controls or a tool that changes them.

- Settings (gear in the rail): General; Appearance; Accessibility; Account; Project secrets; Usage and plan; Models and agent; Browser; Safety; Allowed without asking; Instructions; Voice; Notifications; Privacy and data; Network; Updates; Developer; About.
- Settings > Browser groups Vibe Work browser, Your Chrome, Your Edge and All browsers. Your Chrome and Your Edge setup is here; Chrome's connection card also appears above the connectors in Tools > Connectors.
- `session_status` reports this chat's model alias, thinking level (null when unknown), access mode, running Vibe version, Chrome extension store state and browser add-on states. `addon_suggest` takes `addon` (`chrome` or `edge`) and a `reason` to show a browser card in chat (`vw:chrome`): Connect Chrome or Connect Edge. Edge opens Settings > Browser > Your Edge; initial setup there is Set up….
- Temporary chat can start on Send without choosing a folder, in an empty folder of its own. Quit deletes Temporary chats; failed deletions are retried at startup. Folder removal retries briefly if busy when its chat is deleted, then retries at Quit or startup once no temporary chats remain. Changes outside that folder stay changed.
- Settings > General's Close to tray option is labelled "Keep running in the tray when the window closes" ("menu bar" on macOS). With it on and a tray available, closing the window keeps chats working. Clicking a chat notification reopens that chat; Quit Vibe Work in the tray menu ends the app.
- Chats waiting for an answer show under Needs you. Outside the window: a number on the taskbar button (Windows) or Dock icon (macOS) and a dot on the tray or menu bar icon ("Vibe Work: 1 chat needs your answer"); Linux trays show a "Needs your answer" icon. Viewing the chat removes it from that count until its next prompt. On Windows, a notification still opens its chat from Notification Center after the banner is gone.
- Settings > Network has HTTPS proxy, HTTP proxy, Proxy for anything else (optional), Addresses that skip the proxy (optional), and Company certificate file. The .pem file adds trusted certificates. Proxy addresses support HTTP, HTTPS and SOCKS4/5; proxy sign-in stays in the vault. Addresses that skip the proxy are comma-separated; localhost, 127.0.0.1 and ::1 stay direct. The computer's environment settings override saved values. Settings reports when a restart is needed: saved changes apply to Vibe's shell commands after using Quit Vibe Work and opening the app again; closing to the tray is not a restart. `process_start` has a separate environment inherited when the app started. `session_status.network` reports both proxy routes, exclusions and restart timing without proxy sign-in.
- Voice: microphone, dictation language, read aloud voice, automatic reading and voice chat. `read_aloud({})` reads your previous reply aloud once (`text` for only part of it). This system's screen reader (named in the Vibe Work note) is separate from these controls.
- Models and agent: defaults for new chats ("Access mode") and each model's Compaction point. The access chip below a chat changes only that chat, never the next chat's default.
- In Accept edits, `preview_list`, `preview_console`, `search`, `processes_list`, `port_lease`, `panel_read` and `handbook_answers` run without the default approval card, as do `browser_read` without `tab: "new"`, `handbook_check` without `repair` and `preview_screenshot` without `width`. Stricter user rules still apply. Explicit new tabs, preview resizing/opening and stylesheet repairs still ask. Built-in `browser_act` asks for the same actions as Your Chrome: clicks, typing, form choices, navigation and uploads from the chat's first folder run without a card.
- Browser: this chat's App preview and web pages. Files offers Open and Show in folder for downloads, including in Temporary chats. `preview_list` lists this chat's servers and the free leased ports (`leasedFree`) for `process_start`; `vw:preview` and `vw:browser` have the calls.
- Files: the folder tree, file previews and editor. Terminal: shells in the chosen folder. Changes: review edits and commits. Project Pages: plans, reports and comments. `panel_read` reads the open panel and selection; `search` finds text and file names in this chat's folders.
- Tools in the rail: connectors, MCP servers and skills. Libraries: searchable document collections. Vault: keys and logins (`vw:secrets`).
- Skills a folder pins in `.vibe/skills.toml` are installed from Mistral's skill registry when a chat starts there, without asking; registry skills are on by default. A pin that cannot be fetched (unknown id, no connection) is skipped without a message and the chat starts without it. Tools > Skills lists On this computer and Mistral's catalog, which can be empty.
- Processes > Left running lists agent processes that survived deletion of their chat, with Stop (`vw:processes`).
- Paperclip, paste or drop on the chat: attach files, also before the first message. Their Extracted text is in context; `document_read({path, offset})` reads an attachment, or a file in this chat's folders in place without a copy (nextOffset pages on): without a card in Full access or Accept edits; Ask offers a card first. Word, PowerPoint, Excel, CSV and text are read locally; PDF and images use Mistral OCR quota. Dropping a document in Browser does not read it.
- `video_frames({path, selection, output})` (Windows and macOS only) reads video up to 512 MiB and at most two hours. Selection: `uniform`, `interval`, `timestamps` or `scene_changes`; output: `frame`, `contact_sheet` or `metadata`. At most 24 frames across 10 minutes; `frame` requires one frame. Metadata sends no image; no audio. Chat shows planned frame/image counts before extraction. Decoding depends on this computer; refusals distinguish formats, worker failures and limits. Video is not available on Linux yet; ask for still images.
- Ctrl/Cmd+K searches actions, settings, chats and files. A waiting answer is on the familiar prompt card; Ctrl/Cmd+Shift+A goes to it, including a subagent's card.
- A rendering error shows "The window could not be displayed" with Try again and Reload window (reloads the whole window). A startup error shows "Vibe Work could not start", its reason and "Quit and try opening Vibe Work again."
